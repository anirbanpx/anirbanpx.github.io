Agentic AI · Low-code Builder

The AI Agent Layer — Launchpad's GenAI Builder

2024 — 2026
Problem

Launchpad is Pega's enterprise app-builder — a platform where software companies configure AI-powered applications without writing code. But there was no native way inside Launchpad to configure an AI agent: no way to connect to a language model, declare a knowledge source, or define what tools the agent could use. Builders who wanted AI-powered apps had to write custom code outside the platform. The entire agentic stack was a gap.

The Bet

Study how the best developer tools handle agent configuration — n8n, LangChain, OpenAI's Agent Builder — and build their low-code equivalents inside Launchpad as first-class configuration screens. Three new forms: GenAI Connect (LLM integration and provider configuration), GenAI Agent (the agent declaration UI — goals, memory, behavior), and GenAI Tool (knowledge sources and action definitions). One primitive per layer of the agentic stack.

The Hard Part

Agentic workflows combining LLM calls and tool execution can easily breach the standard 66-second request timeout — silently, with no error returned to the builder. I designed runningMode=async: an API parameter that moves agent execution to the background and returns a session ID the caller uses to retrieve the result when ready. Not a timeout bump — a different execution model that made long-running agents observable and testable for the first time.

Proof it Worked

Won Pega's company-wide 2025 hackathon by building an AI-native, spec-driven to-do list using the exact GenAI primitives I'd shipped. The same features I'd designed for independent software vendors, I used to build something myself. That's the test I care about most.

Outcome

All three GenAI forms shipped May–November 2025. Within 6 months of launch, 100% of new Launchpad apps incorporate GenAI — up from zero at the start of 2025. The async execution model shipped April 2026, unblocking all long-running agentic use cases. Pega's AI agent builder is now the enterprise equivalent of what n8n or OpenAI's Agent Builder is in the developer market.

The best product test for a builder platform is whether the PM who designed it can use it to build something real. I could.

Zero to One · Platform Pivot

PM — content.werally.com, Rally Health

2020 — 2022
Problem

Rally Health had a successful wellness suite but no proprietary content. Each large employer customer wanted a customised member experience — different articles, landing pages, brand voice for their employees. The status quo was bespoke, slow, and required engineering time per employer.

The Bet

Build the platform, not just the content. Ship a focused MVP first to prove demand, then pivot to a content platform that makes per-employer customisation self-serve — eliminating the per-employer engineering overhead entirely. Sequence mattered: prove it works, then make it scale.

The Tradeoff

The content platform pivot in year one was a hard sell. It meant slowing visible feature delivery to build tooling employers wouldn't see directly. The argument: without it, every new employer engagement permanently required engineering time. The bet traded near-term feature velocity for invisible, compounding leverage.

Outcome

100K+ monthly active members in year one, 70% customer satisfaction score. The content platform removed 1.5 full-time engineers of ongoing engineering effort, cut speed-to-market from 30 days to 3 days, and unlocked $3.5M in projected two-year savings. A personalisation layer on top added a 5% lift in 28-day web retention.

The platform bet is always harder to justify until it pays off. The instinct — turn bespoke work into a configurable surface — is the same pattern I've run at Pega ever since.
